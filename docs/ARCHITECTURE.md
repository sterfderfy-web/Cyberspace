# Предлагаемая архитектура первого прототипа

Статус: предложение для согласования, 1 ноября 2026. Стек и схемы ещё не утверждены.
Связанные документы: [ТЗ](MVP.md), [манифест](../MANIFESTO.md), [AGENTS.md](../AGENTS.md).

## Предложение стека

| Компонент | Предложение | Причина и граница |
|---|---|---|
| Язык | TypeScript | Общий язык контрактов, сервера, клиента и демонстрационного агента |
| Среда сервера | Поддерживаемый Node.js LTS | Один процесс для малого локального экземпляра |
| HTTP и подписки | Fastify и @fastify/websocket | Одна точка аутентификации и проверки входных данных |
| Хранилище | SQLite, адаптер за интерфейсом Repository | Локальная база без отдельного сервиса; транзакции для изменения и события |
| Браузер | React + Vite, обычный DOM | Простой редактор, проверяющий независимость ядра от визуализации |
| Сборка репозитория | npm workspaces, lockfile | Общие контракты и воспроизводимые зависимости |
| Проверки | node:test для ядра/сервера; Playwright для браузерного сценария | Проверка поведения API и двух независимых сессий |

Версии, SQLite-драйвер и команды установки выбираются и фиксируются при согласованном старте реализации после проверки совместимости. Здесь не вводится зависимость от конкретного провайдера, облака или LLM. SQLite-драйвер должен работать на целевой ОС и ARM64, если они войдут в согласованную матрицу.

Альтернатива — Python-сервер и TypeScript-клиент: удобна при преобладании Python-модулей, но потребует двух языков и отдельной генерации контрактов. Для текущего малого прототипа предлагается TypeScript; выбор не ограничивает языки будущих совместимых реализаций.

Официальные источники для последующей фиксации зависимостей:

## Компоненты и зависимости

Предлагаемая структура (пока не создана):

- packages/contracts — JSON Schema, транспортные типы и коды ошибок.
- packages/core — сущности, разрешения, выполнение команд; без React, HTTP и SQLite.
- packages/storage-sqlite — схема базы, миграции, реализация Repository.
- packages/module-notes — декларация модуля и обработчики.
- apps/server — HTTP, WebSocket, сессии, связывание компонентов.
- apps/web — индивидуальное представление общего состояния.
- apps/demo-agent — отдельный Actor, тот же сетевой API.
- tests/acceptance — сценарии из ТЗ.

Сервер вызывает ядро и адаптер хранения. Клиенты зависят от открытого контракта; база недоступна им напрямую. Модуль получает ограниченный контекст команды вместо доступа к процессу сервера или базе. В MVP модуль встроенный и доверенный; это не песочница для стороннего кода.

Каждый экземпляр самостоятельно владеет своим состоянием и разрешениями. Идентичность пространства — UUID; сетевой адрес хранится отдельно. Копирование идентификатора не подтверждает подлинность удалённого сервера. Федерация, глобальная идентификация и доверие между серверами требуют отдельного проекта протокола.

## Модель данных

| Сущность | Основные поля | Хранение |
|---|---|---|
| Space | id, name, revision, created_at | Постоянно |
| Object | id, space_id, type, schema_version, properties, revision, created_at, updated_at | Постоянно |
| Actor | id, kind: human/agent/service, display_name, disabled | Постоянно |
| Permission | id, space_id, actor_id, actions | Постоянно |
| Module | id, version, actions, input_schemas, required_permissions | Декларация встроенного модуля |
| Session | id, actor_id, token_hash, expires_at, revoked_at | Серверное хранилище; открытый токен не сохраняется |
| Composition | session-local список ссылок на пространства и параметры вида | Полная сущность отложена; список из одного пространства в MVP |

Дополнительные таблицы: events (последовательность событий пространства), audit (результаты значимых действий), requests (идемпотентность). Индивидуальный выбор заметки и раскладка находятся в памяти вкладки. Перезагрузка вкладки может сбросить их.

Заметка: type = note, properties = { title, text }. Лимиты предложения: заголовок до 200 символов, текст до 64 КиБ UTF-8, запрос до 128 КиБ. Сервер проверяет JSON Schema во время выполнения: TypeScript-типы не заменяют валидацию.

Для MVP права выдаются на всё пространство. Объектные ACL и наследование прав не вводятся.

## Разрешения и сессии

Предлагаемый набор actions: read, write, execute, manage. Это независимые действия:
- снимок и подписка требуют read;
- создание/изменение заметки требует read + write;
- вызов действия модуля дополнительно требует execute;
- выдача/отзыв прав требует read + manage.

Владелец получает все действия. Обычному читателю выдаётся read. Прямые операции над заметками отсутствуют: браузер и агент используют модуль, поэтому редактирующему участнику нужны read + write + execute.

Первичная локальная команда настройки создаёт владельца, второго человека и агента с отдельными случайными учётными секретами. Секреты не входят в git и журналы. Публичной регистрации нет. Человек обменивает секрет на ограниченную по сроку серверную сессию; браузер получает HttpOnly cookie с SameSite=Strict. Агент получает session token в ответе и передаёт его через Authorization: Bearer. Actor из тела запроса не принимается как идентичность.

POST /api/v0/sessions создаёт сессию; DELETE /api/v0/session завершает текущую. Срок сессии в MVP — 8 часов без автоматического продления. Сервер проверяет срок, отзыв и disabled на каждом запросе и перед отправкой события подписчику. При рестарте открытые WebSocket закрываются, действующая сессия может подключиться заново.

Браузер и API обслуживаются с одного origin. Для браузерных изменений обязательны проверка Origin и SameSite cookie; CORS закрыт по умолчанию. WebSocket проверяет cookie и Origin; токены в URL запрещены. Ошибки входа ограничиваются по частоте. За пределами loopback требуется HTTPS/WSS; локальный HTTP допустим только для изолированной демонстрации без передачи настоящих секретов через недоверенную сеть.

Отзыв прав и команды сериализованы в транзакциях одного экземпляра. Действие, уже зафиксированное до отзыва, не отменяется; после подтверждения отзыва новые действия запрещены. Закрытие подписки не может стереть данные, уже полученные клиентом.

## API v0

Это проект контракта. Перед кодом его необходимо выразить в машиночитаемых схемах с примерами.

| Метод и путь | Назначение | Доступ |
|---|---|---|
| POST /api/v0/sessions | Обмен учётного секрета на сессию | Учётный секрет |
| DELETE /api/v0/session | Завершить текущую сессию | Текущая сессия |
| GET /api/v0/spaces | Список доступных пространств | Сессия; только пространства с read |
| GET /api/v0/spaces/:id | Согласованный снимок объектов и cursor | read |
| GET /api/v0/spaces/:id/modules | Декларации доступных модулей | read |
| POST /api/v0/spaces/:id/actions | Вызов действия модуля | read + write + execute для notes |
| GET /api/v0/spaces/:id/permissions | Просмотр правил доступа | read + manage |
| PUT /api/v0/spaces/:id/permissions/:actor_id | Заменить набор прав Actor | read + manage |
| GET /api/v0/spaces/:id/audit | Журнал действий | read + manage |
| GET /api/v0/spaces/:id/export | Версионированный экспорт данных | read + manage |
| POST /api/v0/imports | Импорт в новое пространство | Владелец экземпляра |
| GET /api/v0/spaces/:id/events | WebSocket-подписка | read |

PUT permissions передаёт request_id, expected_space_revision и actions; пустой actions отзывает права. Самостоятельно удалить последнего управляющего нельзя. Импорт принимает request_id и version; лимит файла — 10 МиБ, до 1000 заметок. Импорт валидируется полностью и применяется атомарно. При превышении лимитов — явный отказ.

Пример тела вызова notes.update_note:

```json
{
  "request_id": "52c404ce-60ac-457b-8dbb-44bebeb73aa9",
  "module": "notes",
  "action": "update_note",
  "object_id": "edffdc73-ad7b-40c3-8d52-7dfaa086d185",
  "expected_revision": 3,
  "input": { "title": "Мастерская", "text": "Проверить датчик" }
}
```

notes.create_note не принимает object_id и expected_revision: идентификатор назначает сервер. Успешный ответ содержит request_id, object и space_revision. Ошибка содержит request_id (если он распознан), code и message. HTTP-коды: 400 — схема/версия, 401 — сессия, 403 — права, 404 — недоступная цель, 409 — ревизия/повтор с другим телом, 413 — размер, 429 — частота. Для недоступного пространства используется 404 без раскрытия его существования.

## Согласованность и восстановление

- Изменение объекта, ревизии пространства, запись успешного audit, event и результат request_id фиксируются одной SQLite-транзакцией. Событие публикуется после commit.
- Обновление сверяет expected_revision объекта; права сверяют expected_space_revision. Несовпадение возвращает 409, клиент предлагает перечитать состояние.
- Request ID уникален в пределах Actor + Space (для импорта Actor + instance). Хранятся хеш тела и результат до 24 часов; после этого гарантия дедупликации не действует. Повтор сначала проходит актуальные проверки доступа, затем возвращает сохранённый результат без второго изменения.
- Ошибки разрешений/конфликты записываются отдельно в audit с ограничением частоты; секреты и тексты заметок не записываются.
- WS передаёт уведомление { version, type: "space.changed", space_id, cursor }, без содержимого заметки. Клиент перечитывает снимок; cursor — монотонная ревизия пространства.
- При подписке сервер сначала регистрирует соединение, затем присылает текущий cursor. Клиент буферизует уведомления, получает снимок и повторяет чтение, если видел больший cursor. Это закрывает гонку между снимком и подпиской.
- После разрыва клиент переподключается с задержкой от 0.5 до 10 секунд с jitter и повторяет получение снимка. Replay событий и офлайн-очередь изменений в MVP не нужны.
- Медленные подписчики отключаются при переполнении ограниченной очереди; восстановление происходит через снимок. Heartbeat обнаруживает потерю соединения. Конкретные лимиты соединений фиксируются в конфигурации реализации и проверяются тестами.

## Экспорт и границы доверия

Экспорт version=0 включает имя пространства, типы, schema_version и содержимое заметок. Не включает сессии, секреты, audit и права других участников. Импорт назначает новые Space/Object ID; импортирующий становится владельцем копии. Это перенос данных, а не перенос идентичности или доверия. Неизвестные типы/версии отвергаются.

Демонстрационный агент — отдельный процесс без прямого доступа к базе. Автоматический выбор действий LLM позже подключается адаптером поверх того же API. Реальное оборудование и выполнение произвольных команд ОС в первый этап не входят.

## Проверка и ограничения

При реализации: модульные проверки разрешений, конфликтов и дедупликации; интеграционные проверки транзакций, рестарта, отзыва и восстановления; браузерная проверка двух сессий; полная таблица A01–A14 из ТЗ.

Ограничения: один процесс записи, небольшие текстовые объекты, доверенный встроенный модуль, без федерации, CRDT, 3D и аппаратного управления. SQLite и полный снимок выбраны для масштаба приёмочного сценария. Если нагрузка выйдет за эти границы, оптимизации оформляются отдельными измеряемыми задачами.

Для начала реализации требуется согласовать: границы [MVP](MVP.md), TypeScript/Node.js + React + SQLite, модель выдачи локальных секретов и предложенный контракт v0. Лицензия остаётся отдельным решением владельца.
