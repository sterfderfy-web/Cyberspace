# API v0 локального прототипа

Пространственное дополнение v0: `scene`, `renderers` и команды модуля `spatial` описаны в [SPATIAL.md](SPATIAL.md). Существующие команды заметок и export/import ниже совместимы с PR1–PR3. Экспорт заметок не включает View.

База пути: `/api/v0`. Снимки и команды не зависят от React. Runtime-схемы команд, входа, прав и импорта находятся в `packages/contracts/index.ts`; модуль `notes` возвращает декларацию действий и необходимых разрешений через `/spaces/:id/modules`. Неизвестные поля запросов отвергаются, типы не приводятся автоматически.

## Сессии

`POST /sessions` принимает `{ actor_id, secret, mode }`, где mode — `browser` или `agent`. Учётные секреты выдаёт локальная команда setup. Для входа обоих типов обязателен `Origin`, совпадающий с одним из настроенных сервером адресов.

Для browser ответ содержит Actor и метаданные Session; cookie `cyberspace` имеет HttpOnly, SameSite=Strict, Path=/ и Max-Age=28800. В локальном HTTP-режиме Secure не выставляется. Для agent ответ дополнительно содержит `token`, который передаётся как `Authorization: Bearer <token>`. Не помещайте токен в URL. Сервер хранит SHA256 токена, срок и отзыв; срок сессии — 8 часов, без автоматического продления.

`GET /session` возвращает текущие Actor/Session, `DELETE /session` отзывает сессию и закрывает её подписки. Actor действия всегда определяется по сессии. Нельзя подменить его полем тела команды.

Cookie-изменения требуют разрешённого Origin. Bearer-запросы после входа могут не иметь Origin, но если он указан — должен быть разрешён. CORS не включён. Для браузерной и агентской WS-подписки Origin обязателен; параметры URL запрещены.

## Пространства и заметки

| Метод / путь | Результат | Права |
|---|---|---|
| GET `/spaces` | Массив `{id,name,revision,created_at}` | Только пространства с read |
| GET `/spaces/:id` | `{space,objects,cursor,permissions}` | read |
| GET `/spaces/:id/modules` | Декларация notes v0 | read |
| POST `/spaces/:id/actions` | `{request_id,object,space_revision}` | read + write + execute |
| GET `/spaces/:id/permissions` | Массив `{actor,actions}` | read + manage |
| PUT `/spaces/:id/permissions/:actor_id` | `{request_id,space_revision,actions}` | read + manage |
| GET `/spaces/:id/audit` | Последние 200 записей, новые сначала | read + manage |
| GET `/spaces/:id/export` | Переносимый JSON v0 | read + manage |
| POST `/imports` | `{request_id,space}` | instance_owner |
| GET `/spaces/:id/events` | WebSocket | read |

Ниже UUID — иллюстрации формата, не готовые учётные данные.

```json
{
  "request_id": "52c404ce-60ac-457b-8dbb-44bebeb73aa9",
  "module": "notes",
  "action": "create_note",
  "input": { "title": "План", "text": "Проверить совместное редактирование" }
}
```

При обновлении добавляются обязательные `object_id` и `expected_revision`, action меняется на `update_note`. При создании эти поля запрещены. Ревизия заметки начинается с 1; каждое изменение увеличивает её и ревизию пространства. Заголовок: 1–200 символов; текст: до 65536 байт UTF-8. Обычный запрос: до 128 КиБ.

Объект в ответе:

```json
{
  "id": "edffdc73-ad7b-40c3-8d52-7dfaa086d185",
  "space_id": "ffad6d6b-0013-4e3e-a86c-01fefac6f2a5",
  "type": "note",
  "schema_version": 0,
  "properties": { "title": "План", "text": "Проверить совместное редактирование" },
  "revision": 1,
  "created_at": "2026-11-01T18:00:00.000Z",
  "updated_at": "2026-11-01T18:00:00.000Z"
}
```

Выдача прав заменяет весь набор:

```json
{
  "request_id": "9709f7d5-60b6-4fca-a9db-0d9f7be0901a",
  "expected_space_revision": 2,
  "actions": ["read", "write", "execute"]
}
```

`actions: []` отзывает всё. Удаление последнего действующего управляющего (`read` + `manage`) запрещено. Отзыв не отменяет уже зафиксированную команду; все следующие команды, повторы и чтения проверяют новые права. Потеря read даёт 404 без раскрытия пространства, потеря write/execute/manage при сохранённом read — 403.

## Конфликты, повтор и ошибки

`expected_revision` сверяется с ревизией объекта, `expected_space_revision` — с пространством. Устаревшая ревизия даёт 409 `REVISION_CONFLICT`. Клиент сохраняет черновик и предлагает перечитать снимок; автоматической перезаписи нет.

`request_id` — UUID, область уникальности Actor + Space, для импорта Actor + instance. На 24 часа сохраняются канонический хеш команды (включая действие и цель) и ответ. Повтор проходит **актуальные** проверки прав до поиска результата. Такое же тело возвращает сохранённый ответ; другое — 409 `REQUEST_REUSED`. Порядок ключей JSON не важен. Повтор успешной команды не создаёт второй объект, event или успешную audit-запись. Гарантия заканчивается через 24 часа.

Объект, ревизия пространства, event, audit и результат request_id фиксируются одной транзакцией `BEGIN IMMEDIATE`. Уведомления идут после commit. Тест с принудительным отказом записи event проверяет откат всей транзакции.

Ошибка: `{request_id?, code, message}`. Сообщение человекочитаемое на русском; код предназначен для клиента. Общие HTTP-коды: 400 (схема), 401 (сессия), 403 (права/Origin), 404 (цель недоступна), 409 (конфликт), 413 (лимит размера), 429 (частота), 500 (внутренняя ошибка без подробностей). Audit содержит Actor, Session, request_id, время, действие, цель и результат; не содержит секретов и текста заметок. Повторяющиеся одинаковые отказы одного Actor/Space/Action подавляются в пределах секунды.

## Подписки

Сервер сначала регистрирует соединение, затем присылает текущий cursor. Формат каждого уведомления:

```json
{"version":0,"type":"space.changed","space_id":"ffad6d6b-0013-4e3e-a86c-01fefac6f2a5","cursor":3}
```

Текст заметки в уведомлении отсутствует. Клиент получает снимок при открытии и каждом уведомлении; ответы с cursor меньше уже принятого игнорируются. Повторная подписка всегда приводит к новому снимку. Выбор заметки и черновик хранятся только в памяти вкладки.

Переподключение — экспоненциальная задержка 0.5–10 секунд с jitter ±20%. Heartbeat каждые 15 секунд; отсутствие pong на следующем такте завершает соединение. Перед отправкой и на heartbeat проверяются срок сессии, отзыв, disabled и read. Отзыв read или logout закрывает подписку с кодом 1008. После возвращения прав пользователь нажимает «Обновить».

Лимиты реализации: 100 WS на экземпляр, 8 на токен сессии, исходящий буфер 64 КиБ (закрытие 1013), входящий WS payload 1 КиБ. Клиентские сообщения в подписку не принимаются. Лимит HTTP — 300 запросов/минуту/IP; вход — 15/минуту/IP. Это лимиты малого прототипа, не заявленная производительность.

## Экспорт и импорт

```json
{
  "version": 0,
  "space": { "name": "Мастерская" },
  "objects": [{ "type": "note", "schema_version": 0, "properties": { "title": "План", "text": "Текст" } }]
}
```

В POST `/imports` к этому объекту добавляется `request_id`. До 10 МиБ и 1000 заметок; каждая заметка также ограничена 64 КиБ UTF-8. Неизвестные типы, версии и поля отвергаются целиком до применения. Импорт атомарный, назначает новые Space/Object ID и ревизии 1. Только импортирующий получает права владельца копии. Исходные Actor, Session, токены, audit, идентификаторы и чужие полномочия не импортируются.

Это первая реализованная версия v0, предшествующего исполняемого API нет. Дополнительный GET `/session` служит восстановлению входа браузера. Изменение версии экспорта или команд в будущем требует отдельного описания совместимости; текущий сервер неизвестные версии отвергает.
