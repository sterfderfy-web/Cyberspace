Физические телефон/планшет, FPS дисплея и длительный профиль памяти остаются непроверенными.

Рабочая пользовательская `.local/cyberspace.sqlite` не использовалась тестами и не мигрировалась ими; миграция выполняется при первом запуске новой версии над ней.

Что подтверждено:

- Transform: TRS и мировые координаты дочернего View, наследование видимости/прозрачности, отбрасывание NaN/Infinity, нулевого масштаба, некорректного quaternion, циклов, лишней глубины и чужих родителей.
- API: несколько View одного Object, самостоятельные ревизии, CAS-конфликт, повторы request_id, неизменность исходного текста, удаление только View, запрет удаления родителя с детьми, ACL, рестарт, совместимость snapshot/export заметок.
- Расширение: тестовый модуль создаёт новый тип Object и его View через существующий Core. Дескриптор визуализатора регистрируется без изменения Core; неизвестный Web-клиенту renderer остаётся доступным в списке.
- Миграция: временная база с точной схемой v1, проверенная резервная копия, побайтово равные значения всех старых строк, действующие секрет/сессия после миграции, отсутствие повторной миграции, отказ на будущей версии и откат DDL при ошибке.
- Браузер: восемь документов, девять View, движение/масштаб/смена визуализатора, один commit после drag и отсутствие записи во время движения; два независимых редактора, сохранение конфликтного черновика, восстановление после reload/restart, личная камера и скрытие.
- Потеря ответа после успешной записи: reload сохраняет исходный request_id, повтор не создаёт второй View. Сенсорные touchMove/touchEnd дают одну запись; touchCancel — ни одной.
- Композиция двух источников: отдельный ACL и очистка списка/инспектора после отзыва read. Читатель не получает возможность изменить размещение.
- Прежние сценарии авторизации, аудита, импорта/экспорта и отдельного процесса агента проходят. Измеренные задержки обновления заметок в локальном браузерном прогоне: 153, 46, 41, 42, 42 мс; это не оценка скорости пространственного рендеринга.

Снимок рабочей сцены: `.local/spatial-workspace.png`; отчёты Playwright и временные трассы остаются вне git. Трассы могут содержать сгенерированные тестовые секреты и не публикуются.

Известные границы: WebGL2, фиксированное разрешение текстур-превью, числовой ввод quaternion/масштаба, лимит 256 View/сцену. Vite предупреждает о размере отложенного пространственного JS-модуля (~577 КБ, ~145 КБ gzip). Личная композиция не синхронизируется между устройствами; JSON v0 не переносит View. Реальные телефон/планшет, физическое отключение WAN, XR, CAD, SDR, федерация, ARM64 и целевые 30 FPS не проверены и не заявлены как выполненные. Автоматическая эмуляция сенсорного ввода не заменяет приёмку физического устройства.

## Особенность окружения

На ноутбуке Kaspersky внедряет запрос к `me.kis.v2.scr.kaspersky-labs.com` в HTTP-страницы. Тест блокирует **все** внешние запросы, включая этот скрипт, и отдельно учитывает внедрение окружения. Необязательных внешних запросов приложения не обнаружено; исходный HTML, возвращаемый Fastify до внешнего вмешательства, не содержит внешних ссылок или скрипта Kaspersky. Работа приложения при блокировке проверена, антивирус и его настройки не менялись.

## Воспроизведение и артефакты

После `npm ci` и `npm run build`:

```powershell
npm run check
npm test
$env:CYBERSPACE_TEST_HOST = '192.168.1.104' # замените на текущий Wi-Fi IP
npm run test:browser
npm audit
```

Исходники: `tests/acceptance/api.test.ts`, `process.test.ts`, `browser.spec.ts`, общая изолированная fixture. Локальный HTML-отчёт: `playwright-report/index.html`. Снимки трёх размеров: `.local/screenshots`. Отчёты, трассы, секреты и базы не публикуются в git. Для ручного прогона на устройствах используйте [RUNBOOK.md](RUNBOOK.md).

Открытых FAIL в финальном локальном прогоне нет. Полная физическая приёмка A01/A02/A12 и проверка телефона/планшета остаются за владельцем. 3D, федерация, аппаратное управление и настоящая LLM находятся вне согласованного этапа.
