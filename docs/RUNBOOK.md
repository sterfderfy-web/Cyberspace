# Запуск и проверка в локальной сети

Проверенная конфигурация: Windows 11 Домашняя x64, Node.js 24.22.2 LTS, установленный Microsoft Edge. Docker, WSL, публичный адрес и облако не нужны. Команды выполняются из корня проекта. Для первого скачивания зависимостей нужен интернет; для запуска собранного приложения он не нужен.

## Первичная установка на Windows

```powershell
cd C:\cyberspace
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\cyberspace.ps1 setup
```

`bootstrap.ps1` скачивает переносимый Node.js в `.tools`, сверяет SHA256 с официальным списком, выполняет `npm ci` и сборку. Системная установка Node.js и изменение постоянного PATH не нужны. `ExecutionPolicy Bypass` относится только к этому процессу PowerShell, а не к постоянным настройкам системы.

`setup` запускается **один раз**: создаёт «Мастерскую», владельца, второго человека и детерминированного агента без LLM. Секреты генерируются случайно и сохраняются в локальном `.local/credentials.json`; для запуска агента отдельно создаётся `.local/agent.json` только с его ID, секретом и ID пространства. В SQLite хранятся scrypt-хеши с индивидуальными солями. Существующую базу и секреты повторный setup не перезаписывает. В подготовленной рабочей копии первичная настройка уже выполнена.

## Обычный запуск

```powershell
cd C:\cyberspace
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\cyberspace.ps1 start
```

Оставьте окно работающим. Откройте `http://localhost:3210`. Остановка — Ctrl+C. Повторная команда `start` сохраняет базу, права, журнал и действующие сессии. Сборка нужна только после изменения исходников. Интерфейс и API раздаются одним сервером, с одного origin.

Открыть файл учётных данных на ноутбуке:

```powershell
notepad .\.local\credentials.json
```

Для владельца используйте `owner.id` и `owner.secret`, для второго человека — `member.id` и `member.secret`. Поле `id` целиком вставляется в «ID участника», `secret` — в «Учётный секрет». Секреты не копируйте в issues, логи и git. Для двух людей на одном ноутбуке используйте разные профили браузера или обычное и InPrivate-окно. Вкладки одного профиля используют одну cookie, но имеют независимый выбор заметки и черновик.

## Телефон и планшет

1. Подключите устройства к той же доверенной Wi-Fi сети. Не используйте гостевую сеть с изоляцией клиентов. На время проверки выключите на мобильном устройстве переключение на мобильный интернет при отсутствии интернета в Wi-Fi.
2. На ноутбуке найдите IPv4 именно Wi-Fi адаптера:

```powershell
Get-NetIPConfiguration | Format-List InterfaceAlias,IPv4Address,IPv4DefaultGateway
Get-NetConnectionProfile | Format-Table InterfaceAlias,Name,NetworkCategory
```

При подготовке Wi-Fi «Беспроводная сеть 2» имел адрес `192.168.1.104`, сеть `MERCUSYS_3218`. Адрес может измениться после переподключения. Адреса VMware, ZeroTier и других VPN не нужны для проверки через Wi-Fi.

3. Разрешите порт только для доверенной частной сети. Сейчас у Wi-Fi профиль **Public**. В PowerShell **от имени администратора**, если эта сеть действительно ваша доверенная локальная сеть:

```powershell
Set-NetConnectionProfile -InterfaceAlias 'Беспроводная сеть 2' -NetworkCategory Private
New-NetFirewallRule -DisplayName 'Cyberspace LAN 3210' `
  -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3210 `
  -Profile Private -RemoteAddress LocalSubnet -InterfaceAlias 'Беспроводная сеть 2'
```

Имя адаптера замените на своё, если оно другое. Правило создавайте один раз. Брандмауэр остаётся включённым. Эти системные команды при разработке **не выполнялись**: фактический доступ с других устройств проверяет владелец ноутбука. Если Windows показывает запрос доступа Node.js к сети, разрешайте только частную сеть.

4. При запущенном сервере откройте на телефоне и планшете **`http://192.168.1.104:3210`** (или текущий IP). Не используйте `localhost` на телефоне: это адрес самого телефона. Войдите одним устройством как владелец, другим как участник. HTTP предназначен только для локальной демонстрации с отдельными тестовыми секретами; это не настройка для публикации.

Если страница не открывается, проверьте работу на ноутбуке по тому же LAN-адресу, правильность профиля и правила, общую Wi-Fi сеть, изоляцию клиентов на роутере и включённый сервер. Брандмауэр целиком не отключайте.

После демонстрации необязательное правило можно убрать:

```powershell
Remove-NetFirewallRule -DisplayName 'Cyberspace LAN 3210'
```

## Настройки

Переменные задаются **до** запуска и действуют в текущем окне PowerShell:

```powershell
$env:CYBERSPACE_HOST = '192.168.1.104'
$env:CYBERSPACE_PORT = '3210'
$env:CYBERSPACE_ORIGINS = 'http://192.168.1.104:3210,http://localhost:3210,http://127.0.0.1:3210'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\cyberspace.ps1 start
```

При привязке к конкретному IP открывайте именно его: loopback-адреса могут больше не слушаться. По умолчанию HOST=`0.0.0.0`, PORT=`3210`, разрешённые Origin строятся из localhost, 127.0.0.1 и текущих IPv4 ноутбука. Для ограничения единственным Wi-Fi интерфейсом используйте явный HOST. При смене IP перезапустите сервер. Origin сверяется с разрешённым списком, а не с присланным Host.

| Переменная | Назначение / по умолчанию |
|---|---|
| `CYBERSPACE_DB` | Файл базы: `.local/cyberspace.sqlite` |
| `CYBERSPACE_CREDENTIALS` | Файл секретов для setup: `.local/credentials.json` |
| `CYBERSPACE_AGENT_CREDENTIALS` | Файл только для агента: `.local/agent.json`; setup по умолчанию создаёт agent.json рядом с credentials |
| `CYBERSPACE_HOST`, `CYBERSPACE_PORT` | Адрес прослушивания и порт |
| `CYBERSPACE_ORIGINS` | Разрешённые точные Origin через запятую |
| `CYBERSPACE_SECURE_COOKIE` | `1` добавляет Secure; по умолчанию локальная HTTP-демонстрация без Secure |
| `CYBERSPACE_URL` | Адрес API для агента: `http://127.0.0.1:3210` |
| `CYBERSPACE_AGENT_ID`, `CYBERSPACE_AGENT_SECRET` | Учётные данные агента вместо чтения локального файла |
| `CYBERSPACE_SPACE_ID` | Целевое пространство агента; иначе из credentials / первого доступного |
| `CYBERSPACE_TEST_HOST` | LAN-IP для браузерной проверки; иначе 127.0.0.1 |

Смена `Secure` сама по себе не включает HTTPS. Публичное размещение, TLS и эксплуатационное усиление требуют отдельного этапа; в этой работе публикации нет.

## Агент и отзыв его прав

В другом окне PowerShell:

```powershell
cd C:\cyberspace
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\cyberspace.ps1 agent
```

Агент — отдельный процесс без LLM, не обращающийся к SQLite. Он читает только `.local/agent.json` (без секретов людей) и вызывает обычный HTTP API. На другой машине можно передать только этот файл и явно указать `CYBERSPACE_URL` ноутбука.

1. Нажмите Enter у приглашения `Задание >`. Появится заметка «Результат демо-агента» и подтверждение `OK`.
2. В браузере владельца откройте «Участники и права», у «Демо-агент · без LLM» снимите «Выполнение». Дождитесь «Права обновлены».
3. **Не перезапуская агента**, нажмите Enter снова: ожидается `403 FORBIDDEN`. Новая заметка не создаётся.
4. Откройте «Журнал действий» и нажмите «Обновить»: будут успех и отказ от одного Actor/Session. Включите право обратно при необходимости.
5. `q` и Enter завершают агента и отзывают его сессию.

Одно задание без интерактивного режима при Node.js в PATH: `npm run agent -- --once`.

## Сценарий ручной приёмки на устройствах

1. Владелец создаёт заметку. Участник видит её, но не может сохранить правку.
2. Владелец включает участнику «Изменение» и «Выполнение», оставляя «Чтение». Участник редактирует и сохраняет. Оба видят результат.
3. Создайте вторую заметку. Выбор на телефоне не должен переключать ноутбук или планшет.
4. Два редактора открывают одну заметку и вводят разные черновики. Первый сохраняет; второй видит предупреждение. Его сохранение получает конфликт, черновик остаётся. «Перечитать» с подтверждением загружает серверную версию.
5. Отзовите «Изменение»: новые записи запрещены в открытой сессии. Отзовите «Чтение»: содержимое исчезает из интерфейса, чтение API закрыто. Уже увиденные ранее данные стереть с чужого устройства невозможно.
6. Верните «Чтение», нажмите «Обновить» у участника. Выключите и включите Wi-Fi телефона; при доступном сервере снимок должен восстановиться. Черновик остаётся только в живой вкладке; перезагрузка страницы его сбрасывает.
7. Остановите и запустите сервер. Заметки, ревизии и права должны сохраниться; действующие сессии переподключаются.
8. Отключите интернет **на стороне WAN роутера**, сохранив общую Wi-Fi сеть; повторите запись и задание агенту. Не отключайте Wi-Fi ноутбука для этой проверки.
9. Владелец нажимает «Экспорт» и сохраняет JSON. «Импорт копии» создаёт отдельное пространство с новыми ID и без чужих прав. Выберите его в списке пространств. Для проверки чистого экземпляра используйте другой каталог / пути БД и credentials и другой порт, затем импортируйте туда экспорт.

## Разработка и проверки

С переносимым Node.js добавьте его в PATH **только текущего окна**:

```powershell
$env:PATH = 'C:\cyberspace\.tools\node-v24.22.2-win-x64;' + $env:PATH
npm ci
npm run check
npm run build
npm test
$env:CYBERSPACE_TEST_HOST = '192.168.1.104'
npm run test:browser
```

Браузерный тест на Windows использует установленный Edge. В CI используется Chromium, предварительно установленный командой `npx playwright install --with-deps chromium`. Тестовые базы и секреты генерируются в `.local/tests`, очищаются после тестов и не используют демонстрационную базу. HTML-отчёт — `playwright-report/index.html`, снимки — `.local/screenshots`, трассы неуспешных прогонов — `test-results`. Эти каталоги не входят в git; трассы могут содержать временные тестовые секреты, их не публикуют.

Разработка в двух окнах с Node.js в PATH:

```powershell
# Окно 1
$env:CYBERSPACE_ORIGINS = 'http://127.0.0.1:5173,http://127.0.0.1:3210,http://localhost:3210'
npm run dev
# Окно 2
npm run dev:web
```

Откройте `http://127.0.0.1:5173`: Vite проксирует `/api`, включая WebSocket. Для демонстрации используйте собранный вариант `npm start`.

Без переносимой Windows-установки: установите Node.js 24.22.2 для своей ОС, затем `npm ci`, `npm run build`, `npm run setup`, `npm start`. Linux проверяется отдельно в CI; ARM64 и физические мобильные устройства не входят в выполненную локальную проверку.

## Данные и ограничения

### Пространственная рабочая область

После обновления зависимостей (`npm ci`) и сборки (`npm run build`) запустите сервер обычным способом. При первом открытии старой базы сервер создаст проверенную копию `*.before-v2-<UUID>.sqlite` и применит миграцию v2. Не удаляйте копию до проверки своих данных; не запускайте одновременно старую и новую версии над одним файлом. Подробности восстановления — [SPATIAL.md](SPATIAL.md).

1. Создайте несколько заметок прежним редактором. Откройте «Пространственная область», выберите источник и нажмите «Добавить View». «Ещё один View» создаёт независимое представление того же документа.
2. В режиме «Выбор / перемещение» перетащите панель: размещение записывается при отпускании. «Панорама» перемещает камеру, «Орбита» вращает её. Колесо или жест двумя пальцами меняет масштаб камеры; кнопки +/−, «Спереди», «Показать всё» доступны явно.
3. Выберите View на сцене или в списке. Измените position, scale, quaternion, размер панели, родителя, прозрачность, слой или видимость и нажмите «Сохранить размещение». «Документ» / «Карточка-сводка» меняют отображение без изменения текста. «Удалить View» сохраняет исходную заметку.
4. В личной композиции подключайте доступные пространства, меняйте личный сдвиг источника или «Скрыть у меня». Это влияет только на текущую вкладку. «Видим для всех» относится к общей сцене и требует прав записи.
5. Откройте вторую сессию: общие View должны совпадать, камеры остаются независимыми. При конфликте черновик сохраняется; «Отбросить черновик View» загружает актуальное размещение. При неизвестном результате нажмите «Повторить запрос размещения» с прежней командой.
6. Обновите страницу и вновь откройте пространственную область; затем перезапустите сервер. Подтверждённые View и исходные заметки должны восстановиться. Выполните это также на физическом сенсорном устройстве перед пользовательской приёмкой.

Пространственный клиент требует WebGL2. Неизвестный визуализатор остаётся в списке; при недоступной графике параметры сохранённых View остаются доступны. Полноценный текст находится в «Заметках», панель показывает превью. Личная композиция хранится в sessionStorage, а не переносится между устройствами. Пока запрос имеет неизвестный результат, не закрывайте вкладку до его проверки. Пределы реализации — [SPATIAL.md](SPATIAL.md).

SQLite, её WAL/SHM и локальные секреты находятся вне git. Не удаляйте `.local` для обновления приложения. Для резервной копии сначала остановите сервер, затем скопируйте этот каталог целиком в защищённое место. Запускайте один сервер записи на одну БД.

Сессия действует 8 часов. Выход отзывает её; права перечитываются на каждом запросе и перед уведомлением. `request_id` дедуплицируется 24 часа: после этого повтор может стать новой командой. После неизвестного результата сохранения нажмите «Повторить запрос», не меняя команду. Полноценной offline-очереди, автоматического слияния, загрузки стороннего кода, федерации и модели ИИ здесь нет.
